# Scale Studio 产品与技术架构设计

> 文档状态：方案基线
> 版本：v1.1
> 日期：2026-08-13
> 适用阶段：产品重构与 MVP 设计

> 已确认的 MVP 业务规则以 [`MVP_PRODUCT_DECISIONS.md`](./MVP_PRODUCT_DECISIONS.md) 为准。

## 1. 产品定义

Scale Studio 是一个面向活动、品牌客户和店内装饰场景的“真实空间尺寸验证与方案预览工具”，不是完整的在线图像设计软件。

用户通常已经在其他设计工具中完成视觉稿，再使用 Scale Studio：

1. 将设计素材放入真实店内空间模板。
2. 确定实际制作尺寸、位置和物料关系。
3. 在低保真轮廓和店内实景中判断组合效果。
4. 将确认结果分享给团队、客户或制作方。
5. 导出预览图和尺寸数据。

### 1.1 核心价值

- 将视觉设计连接到真实空间和实际制作尺寸。
- 减少设计方、活动负责人、店铺和制作方之间的沟通误差。
- 让临时活动客户无需复杂注册即可快速使用受授权的店内模板。
- 保留自由画布，支持非店内模板场景。

### 1.2 非目标

第一阶段不以替代 Figma、Canva 或 Photoshop 为目标，不重点建设：

- 复杂图像编辑、滤镜、蒙版和绘画能力。
- 完整品牌资产管理系统。
- 实时多人光标和复杂在线协同编辑。
- 三维空间建模和真实光照渲染。
- 微服务、全球多主数据库等过度基础设施。

## 2. 产品形态与用户角色

| 角色 | 主要能力 |
|---|---|
| 自由画布访客 | 无需登录，临时使用自由画布并导出 |
| 活动成员 | 通过活动邀请获得店铺/空间权限，保存自己的项目 |
| 外部预览者 | 通过只读预览链接查看发布结果 |
| 管理员 | 管理店铺、空间、权限模板、授权、成员、项目和版本 |

第一版不单独建立“匿名用户”和“活动成员”两套身份。未绑定邮箱、手机号或微信的用户统一称为“活动成员”。

## 3. 两条核心使用路径

### 3.1 路径 A：自由画布

```text
打开网站 → 创建自由画布 → 上传设计 → 调整尺寸 → 导出
```

规则：

- 无需登录。
- 不访问店内模板。
- 不云端保存。
- 使用 `sessionStorage` 保存当前标签页的临时数据，避免意外刷新丢失。
- 关闭标签页或浏览器后，临时数据自然失效。
- 用户可以主动导出 PNG、尺寸数据和项目 JSON。

### 3.2 路径 B：店内模板

```text
邀请链接 / 二维码 / 短授权码
→ 验证活动授权
→ 创建或恢复活动成员
→ 建立浏览器会话
→ 进入已授权的店铺和空间
```

用户不需要邮箱、手机验证码或传统密码即可首次进入。

## 4. 活动、成员与身份设计

### 4.1 身份结构

```text
活动工作区：0715-tencent
成员昵称：Stephanie
显示标识：steph-k7
内部成员 ID：随机 UUID
```

- 活动工作区代表一个客户、订单或活动项目。
- 昵称用于团队内展示，可以修改。
- 显示标识用于登录、客服查找和区分同名成员。
- 内部 UUID 是数据库主键，永不因改名而改变。
- 恢复凭证、设备和项目都关联内部 UUID。

用户不需要记忆内部 UUID。

### 4.2 第一次进入活动

1. 用户打开活动邀请链接或输入授权码。
2. 选择“第一次使用”。
3. 输入昵称。
4. 系统生成不可猜测的内部成员 ID 和唯一显示标识。
5. 系统创建活动成员和当前设备会话。
6. 用户可以保存个人继续使用链接、二维码或恢复码。
7. 用户直接进入活动空间。

### 4.3 已有成员进入

1. 用户打开个人继续使用链接或二维码，或在活动入口输入恢复码。
2. 服务端验证凭证未撤销且仍然有效。
3. 服务端为同一个成员建立新设备会话。

### 4.4 跨设备配对

已登录设备可以生成短期有效的：

- 一次性二维码；或
- 设备配对码。

新设备扫码或输入配对码后，绑定到同一个活动成员，不创建重复成员。

规则：

- 默认每位成员允许 2 台活跃设备。
- 管理员可以移除设备、轮换恢复码和解除设备限制。
- 不使用 IP、浏览器版本或设备指纹猜测身份。
- 未配对的手机和电脑会被视为不同成员，这是无实名登录系统的客观边界。

### 4.5 未来正式账号

微信、手机号或邮箱绑定是后续可选升级，不作为首次使用前置条件。

未来一个正式账号可以关联多个活动成员：

```text
正式用户账号
├── 腾讯 7.15 活动成员
├── Nike 8.20 活动成员
└── 自有长期项目
```

## 5. 邀请链接、二维码与授权码

三种入口不是三套授权系统，而是同一条授权方案的三种传递方式。

```text
邀请链接 ─┐
二维码   ─┼→ 授权方案 → 活动成员 → 会话 → 权限
短授权码 ─┘
```

### 5.1 邀请链接

- 使用长随机 Token。
- 适合通过微信、私聊或订单消息发送。
- 访问后服务端完成兑换并跳转到不含 Token 的干净地址。

### 5.2 二维码

- 二维码内容就是邀请链接。
- 适合线下扫码、微信识别和设备配对。

### 5.3 短授权码

- 使用便于人工输入的短码，例如 `AGI-XH-8K4M`。
- 作为邀请链接无法使用时的备用入口。

### 5.4 重要规则

- 链接、二维码或短码决定“能否加入活动”。
- 个人继续使用链接、恢复码或设备配对凭证决定“你是活动中的哪个成员”。
- 共享授权码不能用于设备配对，否则不同成员会被错误绑定成同一身份。
- 授权码不等于用户身份，也不直接作为后续 API 登录凭证。

## 6. 单人授权、共享授权与权限模板

### 6.1 单人客户授权

- 适合一个客户或订单。
- 默认从首次兑换起 30 天。
- 默认 1 位活动成员、2 台设备。
- 可绑定客户备注、公司名称和订单号。
- 支持后台延期、撤销、重置设备和重新签发。

### 6.2 团队共享授权

- 同一个链接或授权码允许多人加入。
- 每个人创建独立活动成员。
- 建议采用统一固定截止日期。
- 创建时必须设置最大成员数，最大 20 人。
- 达到上限后直接拒绝新成员加入。
- 可设置每位成员设备数。

### 6.3 内部权限模板

权限模板只用于管理员快速生成授权，不面向用户销售，也不建设在线支付或套餐购买。它可以控制：

- 可访问店铺。
- 可访问空间。
- 可使用轮廓视图或实景视图。
- 授权有效期。
- 最大成员、设备和项目数量。
- 导出能力。

创建授权时将权限模板复制为授权快照，后续修改模板不会意外改变已经发放的授权。

### 6.4 权限合并

同一活动成员可以兑换多条授权，权限按资源和有效期分别记录。有效权限可以合并展示，但每条授权独立到期和撤销。

## 7. 店铺、空间、版本与双视图

### 7.1 业务层级

```text
店铺
└── 空间
    └── 空间版本
        ├── 真实毫米坐标系
        ├── 装饰位
        ├── 轮廓视图
        └── 实景视图
```

### 7.2 同一空间、两种视图

轮廓视图和实景视图不是两个独立项目，也不是两套物料坐标。

所有用户物料统一保存为：

```text
x_mm, y_mm, width_mm, height_mm, rotation_deg, z_index
```

编辑器根据当前视图，将毫米坐标转换为屏幕像素。因此用户切换视图时，物料位置、尺寸和旋转必须完全一致。

### 7.3 轮廓视图

显示：

- 空间真实宽高和边界。
- 装饰位轮廓。
- 网格、分区和辅助线。
- 安全边距。
- 禁止覆盖区域。
- 固定设施或遮挡物。

装饰位应支持矩形，并为未来圆形、多边形和不规则轮廓保留 `shape_json`。

### 7.4 实景视图

显示：

- 校正后的店内实拍图。
- 用户设计物料。
- 可切换的装饰位和安全区域蒙层。
- 背景透明度和辅助线开关。

### 7.5 后台照片校准

管理员上传实拍图后：

1. 标记装饰平面四角。
2. 输入真实宽高。
3. 系统进行透视拉正。
4. 建立像素与毫米的映射。
5. 保存原图、校正图和校准参数。
6. 在统一毫米坐标系中标记装饰位。

MVP 只支持经过校正的正视实景图，不建设三维透视编辑器。

### 7.6 空间版本

已发布空间版本不可变。

- 新项目使用当前最新已发布版本。
- 旧项目固定引用创建时的空间版本。
- 尺寸、结构、装饰位或校准关系变化时创建新版本。
- 仅替换校准关系一致的照片，可以更新视图素材而不升级空间版本。
- 旧项目提示存在新版，但不自动迁移。

## 8. 编辑器能力

### 8.1 保留现有能力

- 自定义毫米画布。
- 批量上传 PNG、JPG、WebP、SVG。
- 拖放上传与透明边裁剪。
- X/Y、宽高、旋转和层级调整。
- 多选、复制、粘贴和方向键微调。
- 网格、分区、背景和缩放。
- PNG、CSV 和项目 JSON 导出。

### 8.2 MVP 必须补齐

- 上传后自动聚焦新增素材，避免素材不在当前视野。
- 非重叠的批量素材初始排列。
- 适应画布、适应全部内容、适应选中项。
- Undo/Redo。
- 删除恢复或撤销。
- 吸附网格、装饰位和其他物料。
- 左右/上下对齐、等间距分布。
- 越界提示和安全边距。
- 可见的保存、上传和导出状态。
- 大图上传进度和错误反馈。

### 8.3 移动端定位

- 电脑端承担精细编辑。
- 手机端优先支持查看、现场核对、轻量调整和设备配对。
- 第一阶段不要求手机端拥有与桌面端完全相同的编辑效率。

## 9. 项目私密性与外部预览

### 9.1 模板权限与项目权限分离

共享同一个活动授权，只代表成员可访问相同模板，不代表自动看到彼此项目。

项目默认且在 MVP 中保持 `private`。同一共享授权下的成员互相看不到项目。MVP 不建设团队项目库、团队编辑或复制他人项目。

### 9.2 对外只读预览

用户可以将草稿发布为独立预览快照：

```text
工作草稿 → 发布预览 v1 → 生成只读链接
```

预览链接支持：

- 无需登录查看。
- 轮廓版和实景合成版切换。
- 查看尺寸信息。
- 设置撤销状态；链接使用不可猜测的随机 Token。

预览者不能：

- 修改项目。
- 进入活动工作区。
- 查看其他项目。
- 下载空白店内模板和原始校准数据。

草稿继续修改不会自动改变已发布预览。项目拥有者需要主动发布 v2。

## 10. 保存、过期与数据保留

### 10.1 保存规则

- 自由画布：只使用 `sessionStorage`，不云端保存。
- 活动成员项目：云端自动保存，并显示保存状态。
- 项目保存使用 `revision` 或版本号避免多设备覆盖。
- 关键节点可以创建项目版本快照。

### 10.2 授权有效期内

- 创建、编辑和复制店内项目。
- 使用授权范围内的空间和视图。
- 云端保存。
- 团队分享和对外发布。
- 导出预览及尺寸数据。

### 10.3 授权过期后

- 不能新建、复制或编辑店内项目。
- 旧项目只读但可以导出。
- 自由画布继续可用。
- 重新授权后恢复符合权限范围的编辑能力。

### 10.4 数据保留建议

- 项目在授权到期后长期只读保留，除非管理员或项目拥有者主动删除。
- 原始用户图片保留至授权到期后 30 天，优化版本随项目保留。
- 管理员可以延期、恢复或转移项目。
- 第一版通过产品内提示到期，不依赖邮件通知。

## 11. 导出设计

第一版允许：

- 轮廓视图预览 PNG。
- 实景合成预览 PNG。
- 物料尺寸和坐标 CSV。
- 项目 JSON 备份。

后续增强：

- 带空间、版本、日期和项目编号的 PDF 标注稿。
- 安装定位表。
- SVG 输出。
- 原始用户素材打包。

不主动提供：

- 空白店内模板 JSON。
- 全部店内空间数据批量下载。
- 原始照片校准数据。

## 12. 管理后台

### 12.1 店铺与空间

- 店铺和空间管理。
- 真实尺寸和轮廓编辑。
- 装饰位、安全边距和禁止区域标注。
- 实拍图上传和校准。
- 草稿、发布和归档空间版本。

### 12.2 权限模板与授权

- 内部权限模板配置；不包含价格、支付和在线购买。
- 单人和共享授权。
- 邀请链接、二维码和短码生成。
- 最大成员、设备、项目和有效期设置。
- 延期、暂停、撤销和重新签发。

### 12.3 成员与项目

- 活动成员列表。
- 客户名称、订单号和备注。
- 最近使用时间和设备列表。
- 恢复凭证轮换和设备移除。
- 项目恢复、转移和只读状态管理。
- 查看客户项目完整内容。

### 12.4 分享与审计

- 团队可见项目。
- 外部预览链接、有效期和撤销。
- 授权兑换、版本发布和管理员操作日志。

管理员必须使用强身份认证，不沿用活动成员的轻量恢复凭证登录。

## 13. 技术架构

### 13.1 总体架构

采用模块化单体：

```text
Next.js + React + TypeScript
        ↓
服务端 API / 业务模块
        ↓
PostgreSQL
        ↓
COS / OSS 对象存储
```

### 13.2 推荐技术栈

- 前端与服务端：Next.js、React、TypeScript。
- 画布：Fabric.js，业务数据模型与画布库解耦。
- 数据校验：Zod。
- 数据库：PostgreSQL。
- 文件存储：腾讯云 COS 或阿里云 OSS。
- 部署：国内云 Node.js/Docker 环境。
- CDN：国内 CDN。
- 会话：随机不透明 Session Token + HttpOnly Cookie。
- 监控：Sentry 或国内等价服务。

### 13.3 后端模块

- `identity`：活动成员、恢复凭证、设备和会话。
- `authorization`：权限模板、授权方案、Token、兑换记录和权限。
- `catalog`：店铺、空间、版本、视图和装饰位。
- `projects`：项目、项目版本和物料。
- `sharing`：团队权限、预览快照和分享 Token。
- `assets`：用户素材、店内照片和派生图片。
- `admin`：管理后台和管理员权限。
- `audit`：关键操作日志。

### 13.4 第一阶段不需要

- 微服务。
- Kubernetes。
- Redis。
- 消息队列。
- 全球多主数据库。
- 强制第三方用户认证平台。

当授权码猜测攻击、并发、异步导出或实时协作成为真实瓶颈时，再引入 Redis 和任务队列。

## 14. 核心数据模型

| 表/实体 | 作用 |
|---|---|
| `activity_workspaces` | 客户活动或项目工作区 |
| `activity_members` | 活动成员、昵称和显示标识 |
| `device_sessions` | 浏览器会话、设备绑定和撤销状态 |
| `member_recovery_tokens` | 个人继续使用链接、二维码和恢复码的哈希记录 |
| `access_profiles` | 管理员内部使用的权限模板 |
| `access_profile_scopes` | 权限模板包含的店铺、空间和视图 |
| `access_offers` | 一次具体授权方案 |
| `access_tokens` | 邀请链接和短授权码的哈希记录 |
| `access_redemptions` | 授权兑换记录 |
| `access_grants` | 成员实际持有的资源权限快照 |
| `stores` | 店铺 |
| `spaces` | 店内空间 |
| `space_versions` | 不可变的已发布空间版本 |
| `space_views` | 轮廓或实景视图及校准参数 |
| `decoration_slots` | 装饰位、形状、限制和安全边距 |
| `projects` | 用户项目、空间版本和可见性 |
| `project_revisions` | 自动保存和手动版本快照 |
| `project_items` | 物料毫米坐标、尺寸、旋转和层级 |
| `assets` | 文件元数据和对象存储路径 |
| `share_snapshots` | 已发布的只读预览版本 |
| `share_tokens` | 预览链接 Token、有效期和撤销状态 |
| `audit_events` | 授权、发布、撤销和管理员操作日志 |

## 15. API 边界

建议的服务端能力：

```text
POST /api/access/redeem
POST /api/members/create
POST /api/members/recover
POST /api/devices/pair
GET  /api/grants

GET  /api/stores
GET  /api/spaces
GET  /api/spaces/:id/versions/:versionId

POST /api/projects
PATCH /api/projects/:id
POST /api/projects/:id/revisions
POST /api/projects/:id/publish

POST /api/assets/upload-url
POST /api/shares/:id/revoke
```

敏感规则：

- 每个 API 都在服务端重新验证会话和授权。
- 店内数据不能静态打包进前端后再通过 CSS 隐藏。
- 对象存储使用私有资源和短时效签名地址。
- 服务端管理员密钥不能进入浏览器。

## 16. 安全与隐私

- Session Token 使用高强度随机值，数据库只保存哈希。
- Session Cookie 使用 `HttpOnly`、`Secure`、合适的 `SameSite`。
- 个人恢复 Token 和恢复码只保存哈希，支持轮换、过期和撤销。
- 邀请 Token 和短码不保存明文，支持撤销和频率限制。
- 授权兑换必须使用数据库事务，避免人数上限被并发绕过。
- 用户不能仅凭可猜测的活动 ID 和昵称登录他人身份。
- 项目默认私有；共享必须由项目拥有者显式开启。
- 记录必要的安全和审计信息，不使用侵入性设备指纹。
- 店内模板不是高机密，但客户设计项目按敏感数据对待。

## 17. 中国大陆优先与海外扩展

### 17.1 中国大陆首发

- 使用国内正式域名和备案。
- Next.js 以 Docker 形式部署到腾讯云或阿里云。
- PostgreSQL 和应用部署在相近区域。
- COS/OSS 保存实拍图、用户素材和导出文件。
- CDN 承担静态资源和可公开预览资产。

### 17.2 海外扩展

- 复用同一套 Docker 镜像和数据库迁移。
- 为海外用户增加海外应用区域和对象存储。
- 项目按所属区域写入主要数据库，不在第一阶段建设全球多主写入。
- 使用存储适配层和标准 PostgreSQL，降低云厂商绑定。

## 19. MVP 验收原则

MVP 完成时必须满足：

1. 自由画布无需登录，刷新可恢复，关闭后不长期保存。
2. 用户可以通过链接、二维码或短码加入活动。
3. 共享码下的不同成员会生成不同活动成员身份。
4. 同一成员可以通过个人链接、恢复码或配对码跨设备。
5. 授权能精确控制店铺、空间和视图，且共享授权最多 20 人。
6. 不同活动和成员不能访问未授权模板或他人私有项目。
7. 轮廓和实景视图使用同一毫米坐标，切换无位置偏移。
8. 旧项目固定使用原空间版本。
9. 项目默认私有，团队成员互相不可见；只能主动发布只读预览。
10. 授权过期后不能新建或编辑店内项目，但旧项目可只读导出。
11. 管理员能够查看授权、成员、设备、项目和审计记录。
12. 中国大陆部署可用，并为海外区域迁移保留标准化边界。

## 20. 当前默认产品规则

- 自由画布不登录、不云端保存，保留 `sessionStorage` 意外刷新恢复。
- 店内模板使用轻量活动成员身份，不强制邮箱或手机号。
- 首次进入只填写昵称，系统自动生成内部身份和个人恢复凭证。
- 单人授权默认首次兑换后 30 天。
- 共享授权默认统一截止日期。
- 默认每位成员允许 2 台设备。
- 权限可按店铺、空间和视图配置。
- 轮廓和实景是同一空间的两种视图。
- 实拍图由后台校准为正视图。
- 项目默认私有，MVP 不提供团队项目库或团队编辑。
- 外部分享采用可撤销的只读发布快照。
- 空间版本不可变，旧项目固定旧版本。
- 授权过期后旧项目只读可导出，新项目需要重新授权。
