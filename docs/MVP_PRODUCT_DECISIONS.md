# Scale Studio MVP 产品决策记录

> 状态：已确认，可直接进入设计与开发
> 决策日期：2026-08-13
> 作用：本文件是 MVP 范围和业务规则的最高优先级基线；与旧文档冲突时，以本文件为准。

## 1. 产品边界

Scale Studio 是真实空间尺寸验证与效果预览工具，不是在线图像设计软件。

MVP 核心流程：

```text
邀请链接 / 二维码 / 授权码
→ 填写昵称并建立成员身份
→ 获得指定店铺与空间权限
→ 选择轮廓图或实拍图
→ 上传设计物料
→ 调整实际尺寸与位置
→ 云端自动保存
→ 发布只读分享预览
```

明确不会建设：

- 在线支付。
- 套餐购买。
- 支付后的自动开通。

后台可以保留“权限模板”帮助管理员快速创建授权，但它只是内部配置工具，不是面向用户出售的套餐。

MVP 暂不建设：

- 多人实时编辑。
- 团队公共项目库。
- 评论与批注。
- 邮箱、手机号或微信强制登录。
- AI 生图和 Photoshop 级编辑。
- 三维空间预览。

## 2. 设备定位

- 电脑和平板承担完整、精确的画布编辑。
- 手机支持打开邀请、建立身份、查看店铺空间、查看项目、切换轮廓/实拍视图、查看分享预览和少量轻量调整。
- 第一版不要求手机拥有与电脑完全相同的编辑效率。

## 3. 游客自由画布

游客无需登录，可以：

- 创建自定义画布。
- 上传设计物料。
- 调整尺寸和位置。
- 导出预览图。
- 导出尺寸数据和项目 JSON。
- 使用 `sessionStorage` 在当前标签页内恢复意外刷新。

游客不能：

- 查看店铺空间数据。
- 使用店内模板。
- 云端保存。
- 跨设备恢复。
- 创建长期分享链接。

关闭标签页后不保留游客项目。

## 4. 身份与跨设备

- 用户首次进入只填写昵称。
- 系统自动生成不可猜测的内部成员 ID。
- 昵称只负责展示，不是登录凭证。
- 活动授权与个人身份分离。
- 第一版必须支持跨设备恢复同一个成员身份。

跨设备采用：

- 个人继续使用链接或二维码；以及
- 可人工输入的一次性或可轮换恢复码。

活动邀请链接、活动二维码和共享授权码只负责允许用户加入活动，不能用来冒充某个既有成员。

## 5. 授权规则

- 支持单人授权和共享授权。
- 创建共享授权时必须明确最大成员数。
- 最大允许配置为 20 人。
- 达到人数上限后，直接禁止新成员加入，并提示联系店铺。
- 成员上限的判断必须在数据库事务内执行，防止并发超额。
- 授权范围可以精确到店铺和空间。
- 默认授权有效期为一个月，后台可调整。

## 6. 授权过期

过期后：

- 不能创建新的店内模板项目。
- 不能继续编辑已有店内模板项目。
- 已有项目保持只读，可以查看和导出。
- 已发布的只读预览仍可访问，除非分享被撤销。
- 自定义自由画布不受影响。
- 重新获得相同资源授权后，可以恢复符合范围的项目编辑。

项目不会因为授权到期而自动删除；除非管理员或项目拥有者主动删除。

## 7. 项目可见性与分享

- 项目默认私密。
- 使用同一个共享授权的成员互相看不到项目。
- MVP 不提供团队项目库。
- MVP 不提供项目复制给他人。
- MVP 只提供不可猜测、可撤销的只读分享链接。
- 只读预览不能进入活动工作区，也不能读取其他项目或空白模板数据。

## 8. 第一批店铺数据

- 第一版录入上海店。
- 上海店已有的空间数据全部录入。
- 空间均有实拍图和真实尺寸。
- 店铺资料将通过飞书文档提供。
- 部分尺寸写在图片中，需要读取图片标注并结构化录入。
- 在真实资料到位前，开发允许使用明确标识的模拟数据。

## 9. 编辑器 MVP 范围

必须包含：

- 自定义画布尺寸。
- 店铺空间模板。
- PNG、JPG、WebP 上传。
- 拖动、缩放、旋转。
- 输入真实宽高。
- 锁定宽高比。
- 复制、删除和调整层级。
- Undo / Redo。
- 轮廓图与实拍图无位置偏移切换。
- 自动保存与可见保存状态。
- 项目重命名。
- 导出预览图、尺寸数据和项目 JSON。
- 发布只读分享链接。

## 10. 管理后台

MVP 只有一位管理员使用，不建设复杂员工角色体系。

管理员可以：

- 管理店铺、空间、真实尺寸和空间版本。
- 上传轮廓图、实拍图和校准数据。
- 管理装饰位、安全区域和禁止区域。
- 创建单人或共享授权。
- 设置店铺、空间、有效期和成员上限。
- 生成邀请链接、二维码和短授权码。
- 查看成员、设备、活跃时间和项目数量。
- 查看客户项目的完整内容。
- 撤销成员、授权和分享链接。
- 查看关键操作日志。

管理员必须使用强身份认证，不能使用活动成员的轻量身份方式。

## 11. 数量和文件限制

- 每位成员最多 20 个云端项目。
- 单张上传图片最多 15 MB。
- 单个项目最多 30 个物料。
- 上传后生成适合网页使用的优化版本。
- 原始用户图片保留至授权到期后 30 天；优化版本随项目保留。
- 项目长期保留，除非主动删除。
- 分享链接默认随项目持续有效，管理员或项目拥有者可以单独撤销。

这些值应当做成服务端配置，不硬编码在界面逻辑中。

## 12. 产品语言

- MVP 使用简体中文。
- 代码从第一版开始支持国际化资源结构。
- 用户可见文案不散落在组件内部。
- 店铺和空间数据模型支持中英文名称。

## 13. 视觉工作方式

- 用户会提供 Logo、品牌色、店铺资料。
- 暂无参考产品截图不阻塞开发。
- 开发方先提出两个视觉方向供选择。
- 在视觉方向确认前只建立最小 Design Tokens 和低保真产品骨架，不进行大规模视觉精修。

## 14. 测试与发布目标

- 第一阶段必须生成可以直接分享给测试者访问的线上版本。
- v0.1 先以可操作的公开原型验证完整任务路径，并清楚标注浏览器存储与快照链接的边界。
- 正式用户测试版需要真实前后端流程，不只是一组静态页面；完成服务端权限校验后才接收正式客户数据。
- 第一版优先服务中国大陆测试者，但技术结构需保留海外部署能力。
- 正式中国大陆生产部署、备案和域名可以在测试流程验证后单独处理。

## 15. 第一条纵向交付路径

第一条完整切片固定为：

```text
打开活动邀请
→ 创建成员
→ 获得上海店授权空间
→ 选择空间和视图
→ 创建绑定空间版本的项目
→ 进入编辑器
→ 保存项目
→ 发布只读预览
→ 在另一设备恢复成员并查看项目
```

完成标准包括正常流程、权限错误、成员满额、授权过期、加载状态、空状态、移动端查看和基础响应式。
